# M0: Scaffold

Status: done, waiting for owner review.

## What's in it

**Monorepo**

- npm workspaces: `config/`, `packages/*` (8 skeleton packages with READMEs), `apps/web`.
- `config/brand.ts`: app name, tagline, domain, and source URL in one place.
- Strict TypeScript 6.0.3, ESLint 10 (typescript-eslint type-aware rules, React hooks, jsx-a11y strict), Prettier. Lint stops packages from using DOM globals.
- Exact version pins (`.npmrc` `save-exact`), Node 24.22.3 in `.nvmrc`.

**Web app shell** (`apps/web`)

- Vite 8 + React 19 + React Router 8 + Tailwind CSS 4.
- Theme tokens with dark, light, and high-contrast themes, tested for WCAG AA contrast (AAA text in high contrast). Tailwind's default palette is off.
- Self-hosted fonts (Lexend, JetBrains Mono).
- All UI text in an i18next catalog with type-checked keys.
- Skip link, visible focus rings, reduced-motion support, 44 px touch targets.
- `BASE_PATH` support for hosting in a folder (tested in CI with `/cube/`).

**Built-in Guide**

- Markdown in `docs/guide/` compiled at build time (unified/remark), with `{#anchor}` headings, offline search (MiniSearch), and `<GuideLink>` so titles and setting labels open their Guide entries.
- Starter pages: Welcome, Privacy, Settings, Diagnostics, Glossary.
- `npm run check:guide`: every registered feature and setting has a Guide anchor, no duplicates, no broken links.

**cubing.js smoke test**

- `/diagnostics` page: random-state scramble (cubing.js worker), solve, verify. e2e-tested in the production build, in the dev server, and through Caddy with the real security headers.
- Fixed a Vite/Rolldown bundling bug that crashed cubing.js's worker (see LESSONS.md).

**Full-mode stack** (`deploy/`, `server/`)

- PocketBase 0.40.6 image built from a checksum-verified download on a digest-pinned Alpine base, running as a non-root user.
- Caddy 2.11.9 (digest-pinned) serving the app, proxying `/api`, `/healthz`, blocking `/_/` (admin UI), and a password-protected `/admin-home/` page with health and versions.
- Security headers including a Content-Security-Policy.
- Behind-your-own-proxy mode (default) and standalone HTTPS mode. Healthchecks on both services.
- `.env.example` with every value explained.

**Tooling and CI**

- `make` targets: `dev` (HTTPS on the LAN via mkcert or self-signed), `build`, `test`, `e2e`, `ci`, `up`, `down`, `logs`.
- `npm run check:licenses`: fails on any npm package outside the approved open-source license list.
- `tools/version-report.ts`: versions for the admin page.
- GitHub Actions (actions pinned by SHA): lint, format, types, unit tests, Guide check, license check, build; e2e at `/` and `/cube/`; full Docker stack with route checks and e2e through Caddy.

**Docs**

- `CLAUDE.md`, `README.md`, `THIRD_PARTY_NOTICES.md`, `docs/DEVELOPMENT.md`, `docs/UPGRADES.md`, `docs/LESSONS.md`, `deploy/README.md`, `docs/LICENSE-CONTENT.md`, MPL-2.0 `LICENSE`.
